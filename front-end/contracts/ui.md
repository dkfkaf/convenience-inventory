# 화면 및 연동 계약

[요구사항 명세](../../spec.md) · [데이터 모델](../../db/data-model.md) · [검수 가이드](../../test/quickstart.md)

하나의 점포 관리자가 한국어 브라우저 화면에서 흐름을 수행한다. 모든 조회는 같은 점포 시간대를 사용한다. 아래 경로와 입력은 Flask 연동을 위한 기준이다. 프론트엔드 기술과 요청·응답의 표현은 T002에서 팀이 확정한다.

## 팀 결정과 화면별 소스 경로

| 결정 항목 | 현재 상태 |
| --- | --- |
| 프론트엔드 기술과 로컬 실행·빌드 방법 | 미정 · T002에서 팀 합의 |
| 화면 소스 경로 | `front-end/` 안의 세부 경로는 T002에서 공통·오류, 상품·재고·판매, 위험, 폐기·이력, 프로모션의 경로를 기록 |
| Flask 연동 상세 | 미정 · T002에서 입력 인코딩, 응답 표현, 저장 후 이동 및 요청 보호 방식을 기록 |

T002를 마치면 관련 프론트엔드 작업에 실제 파일 경로를 추가하고, 테스트 담당이 합의된 연동 방식에 맞춰 검수한다.

## 조회 화면

| 경로 | 입력과 사용 목적 | 화면에 보여줄 결과 |
| --- | --- | --- |
| 시작 화면 | 브라우저 진입 경로는 T002에서 확정 | 재고 화면과 재고·판매·위험·프로모션·폐기·이력 메뉴를 제공한다. |
| `GET /products` | 상품 목록 | 이름·판매가·기본 매입원가, 상품별 보유·판매 가능·기한 경과 수량, 상품 등록 폼을 표시한다. |
| `GET /products/<product_id>` | 상품 상세 | 로트 ID·잔량·소비기한·적용 원가, 상품 정보 수정과 로트 등록 폼을 표시한다. |
| `GET /sales` | `product_id`, `from`, `to`로 판매기록을 조회 | 판매일·상품·판매수량·연결 로트별 차감, 새 판매 폼과 최근 날짜의 확인·미확인 상태를 표시한다. 확인일을 설정하거나 취소할 수 있다. |
| `GET /risks` | 선택 필터 `kind`에 `expiring`, `expired`, `disposal_risk` 또는 `unsold` | 소비기한 임박·경과, 폐기 위험, 장기 미판매를 표시한다. 상품별 근거에 기준일, 확인일 수, 일평균 판매량, 예상 판매·미판매 수량, 예상 폐기 원가를 보여준다. 예측·판정 보류에는 사유를 표시한다. |
| `GET /promotions` | 위험 상품에서 후보 조회 | 가장 가까운 위험 소비기한 우선, 이후 장기 미판매 단독 후보 순. 상품을 한 번 표시하고 적용되는 위험 사유를 모두 표시한다. |
| `GET /promotions/<product_id>` | 상품별 비교 근거 | 기준 판매가·매입원가, 판매 가능 수량, 3개 판매 방식의 구성당 매출·원가·이익·개당 이익, 구성 가능 여부와 경고를 표시한다. 후보에는 우선 검토 안 또는 검토 유보를 표시한다. 목록을 연 뒤 자정이나 재고 변동으로 후보 자격이 바뀌면 현재 상태를 표시한다. |
| `GET /waste` | `product_id`, `from`, `to`로 폐기일 기준 조회 | 로트·폐기일·수량·사유·적용 원가, 기간 내 상품별 폐기량·폐기 손실, 폐기 폼을 표시한다. |
| `GET /movements` | `product_id`, `from`, `to`로 원인의 업무일 기준 조회 | 로트·업무일·기록 시각·변동 유형·부호 있는 수량·원인 기록을 표시한다. |

기간 필터는 ISO 날짜이며 양끝을 포함한다. 상품·기간 필터는 선택 항목이며, 비어 있으면 해당 조건으로 제한하지 않는다. 오류가 있는 날짜나 시작일이 종료일보다 늦은 입력은 화면에서 수정할 수 있게 안내한다. 조회 건수가 0이면 빈 결과임을 표시하고 합계는 0으로 표시한다.

## 변경 요청

| 경로 | 주요 필드 | 처리 결과 |
| --- | --- | --- |
| `POST /products` | `name`, `sale_price_won`, `purchase_cost_won` | 상품을 만들고 상세 화면으로 이동한다. |
| `POST /products/<product_id>` | `name`, `sale_price_won`, `purchase_cost_won` | 상품 정보를 수정하고 상세 화면으로 이동한다. |
| `POST /products/<product_id>/lots` | `quantity`, `expiry_kind`(`dated` 또는 `none`), `expires_on`, 선택 `unit_cost_won`, `request_key` | 로트와 등록 이력을 기록하고 상세로 돌아간다. 날짜 있음에는 유효한 날짜가 필요하고, 기한 없음에는 날짜 입력이 비어 있어야 한다. |
| `POST /sales` | `product_id`, `quantity`, `request_key` | 판매 업무일을 기록하고 로트별 차감을 반영한다. 판매 목록에서 처리된 판매와 이력을 확인할 수 있다. |
| `POST /sales/day-confirmations` | `sales_on`, `confirmed`(`true` 또는 `false`) | 지난 날짜의 판매기록에 확인 또는 확인 취소를 적용한다. |
| `POST /waste` | `lot_id`, `disposed_on`, `quantity`, `reason`, `request_key` | 로트 감소·폐기·이력을 반영한다. 폐기 목록에서 처리된 폐기와 실제 손실을 확인한다. |

`request_key`는 개별 재고 변경 작업을 식별하는 UUID다. 같은 작업을 재전송할 때는 같은 키를 유지하고, 새 작업에는 새 키를 발급한다. 변경 요청 보호는 T002에서 정한 화면 연동 구조에 맞게 적용한다.

| 상태 | 사용자가 보는 동작 |
| --- | --- |
| 조회 성공 | 요청한 화면 값을 표시한다. |
| 저장 성공 또는 같은 키·입력 재전송 | 완료된 기록과 갱신된 결과를 보여준다. 같은 작업의 재전송은 기존 결과를 사용한다. |
| `422` | 잘못된 입력과 관련 필드를 표시하고 정상 입력값을 유지한다. |
| `403` / `404` | 변경 요청 보호 검증에 실패하면 다시 시도할 방법을 안내한다. 존재하지 않는 상품·로트에는 찾을 수 없음 상태와 목록 링크를 표시한다. |
| `409` | 판매 가능 재고 부족·폐기 잔량 초과 또는 변경된 입력의 요청 키 재사용을 설명한다. 수량과 기록은 반영되지 않는다. |
| `503` | 다른 작업이 처리 중이라면 잠시 뒤 같은 폼을 재시도할 수 있도록 안내한다. |

재고·판매·폐기 수량은 개 단위 정수로 표시한다. 예상량과 개당 이익은 최대 소수 둘째 자리로 표시한다. 경고와 검토 후보의 판정은 원래 계산값을 사용한다.
