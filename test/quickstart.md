# 시연 및 검수 가이드

[구현 계획](../plan.md) · [화면 계약](../front-end/contracts/ui.md) · [명세의 검수 시나리오](../spec.md#사용자-시나리오-및-검수)

아래 명령은 구현을 마친 뒤 저장소 루트에서 실행한다. Python 3.12, MySQL 8.4 LTS, Windows PowerShell 7과 브라우저를 준비한다. 프론트엔드 실행 방법과 접속 주소는 팀이 [화면 계약](../front-end/contracts/ui.md#팀-결정과-화면별-소스-경로)에 기록한다.

## 별도 MySQL 검수 스키마로 실행

로컬 또는 팀 검수용 MySQL에서 `convenience_inventory_demo`와 `convenience_inventory_test`라는 별도 빈 스키마를 `utf8mb4`로 준비한다. 두 스키마에 필요한 권한을 받은 개발용 계정을 사용한다. `init-db`는 현재 시연 스키마의 테이블을 준비하고 기존 데이터는 보존한다. `seed-demo`는 비어 있는 시연 스키마에 가상 데이터를 입력한다. 시연을 처음부터 반복하려면 새 시연 스키마를 준비하고 연결값을 바꾼다.

```powershell
python --version
python -m venv .venv
$python = '.\.venv\Scripts\python.exe'
& $python -m pip install -r backend/requirements.txt -r test/requirements-dev.txt

$env:INVENTORY_DB_HOST = '127.0.0.1'
$env:INVENTORY_DB_PORT = '3306'
$env:INVENTORY_DB_USER = Read-Host 'MySQL 검수용 사용자'
$env:INVENTORY_DB_PASSWORD = Read-Host 'MySQL 검수용 비밀번호' -MaskInput
$env:INVENTORY_DB_NAME = 'convenience_inventory_demo'
$env:INVENTORY_TEST_DB_NAME = 'convenience_inventory_test'
$env:INVENTORY_DEMO_DATE = '2026-11-18'

& $python -m flask --app backend.inventory_app init-db
& $python -m flask --app backend.inventory_app seed-demo
& $python -m pytest -v test
& $python -m flask --app backend.inventory_app run --host 127.0.0.1
```

자동 검수는 `INVENTORY_TEST_DB_NAME`으로 설정한 테스트 스키마만 사용한다. 동시 차감 검수는 같은 테스트 스키마에 MySQL 연결 두 개를 열어 진행한다. 프론트엔드는 T002에서 정한 명령과 브라우저 주소를 사용한다. `INVENTORY_DEMO_DATE`는 가상 데이터의 기준일이며 실제 점포 날짜로 동작할 때는 비운다.

## 화면 시연 순서

| 시연 | 화면과 준비 | 확인할 결과 |
| --- | --- | --- |
| 1. 등록과 판매 | **상품**에서 판매가 2,000원·원가 1,100원 상품과 기한이 다른 5개·8개 로트를 등록한다. 시연 데이터의 다른 상품에서 기한이 다른 2개·5개 로트를 확인하고 **판매**에서 4개를 기록한다. | 새 상품의 총 보유는 13개다. 판매 4개는 빠른 기한 로트 2개와 다음 로트 2개로 나뉘고, 판매기록과 변동이력에서 각각 확인된다. |
| 2. 판매 가능 수량 초과 | 기한 경과 3개와 판매 가능 5개가 있는 상품에 6개 판매를 입력한다. | 부족 사유가 표시되며 수량·판매기록·변동이력에 추가 반영이 없다. |
| 3. 위험 계산 | **위험**에서 최근 확정 판매가 21개이고 오늘까지인 5개 로트와 이틀 뒤까지인 8개 로트가 있는 상품을 조회한다. | 일평균은 3개다. 예상 판매는 각각 3개·6개, 예상 미판매는 2개씩, 예상 폐기 원가는 2,200원씩이다. |
| 4. 0과 미확인 | 기한 없는 장기 미판매 상품을 확인한다. **판매**에서 직전 7일 중 한 날짜를 미확인으로 바꾸고 위험을 다시 조회한다. 기한 임박·경과도 함께 조회한 뒤 날짜를 재확인한다. | 7일이 확인되면 판매 0인 상품에 장기 미판매가 표시된다. 하루를 해제하면 예측과 해당 판정이 보류된다. 판매기록이 있는 상품은 판매가 있었음을 표시한다. 기한 알림은 날짜에 따라 계속 표시된다. |
| 5. 당일과 다음 날 | 오늘이 소비기한인 2개 로트를 조회한 뒤 서버를 정지한다. 이 DB에서 판매·폐기 처리 없이 `INVENTORY_DEMO_DATE`를 `2026-11-19`로 바꾸고 재실행한다. 검수 뒤 원래 날짜로 되돌린다. | 당일에 판매 가능 2개와 임박을 표시한다. 다음 날에는 보유 2개, 기한 경과 2개, 판매 가능 0개를 표시한다. |
| 6. 비교와 구성 수량 | **프로모션**에서 판매가 2,000원·원가 1,100원 상품을 조회한다. 판매 가능 6개와 2개인 예시에서 각각 비교한다. | 개당 이익은 정상 900원, 1+1 −100원, 2+1 약 233.33원이다. 6개일 때 2+1 검토와 저수익 표시, 2개일 때 구성 재고 부족과 검토 유보가 표시된다. |
| 7. 폐기와 원가 이력 | **폐기**에서 원가 1,100원이고 잔량이 5개인 로트의 3개를 폐기한다. 상품 원가를 1,400원으로 수정하고 해당 기간 폐기와 이력을 다시 조회한다. | 잔량 2개, 폐기량 3개, 폐기 손실 3,300원과 −3개 이력 한 건이 표시된다. 기존 폐기 손실은 3,300원으로 유지된다. |

## 자동 검수 대응

| 검수 모듈 | 명세 시나리오 | 자동 확인 |
| --- | --- | --- |
| `test_inventory.py` | S1-1, S1-2, S1-3, S4-1, S4-2, S4-3 | 동일 키와 다른 키 재시도, 동시 판매·폐기, 이력 쓰기 오류 롤백, 로트별 증감 합계, 폐기 원가 유지 |
| `test_risk.py` | S2-1, S2-2, S2-3, S2-4, S2-5 | 오늘을 뺀 7일, 자정 전후, 임박 3·4일 경계, 기한 없는 미판매, 알려진 판매가 있는 미확인일, 최초 등록 후 7일 미만 |
| `test_promotions.py` | S3-1, S3-2, S3-3, S3-4 | 판매 방식별 구성당 이익과 개당 이익, 손익분기와 정확히 50%, 재고 부족, 후보 중복 제거·정렬 |
| `test_web.py` | S1-1, S2-2, S3-1, S4-1, S4-2 | T002에서 합의한 연동 방식에 따른 저장 결과, 중복 제출, 필터·빈 결과, 입력 오류와 충돌, 변경 요청 보호 |

검수는 [성공 기준 SC-01~SC-05](../spec.md#성공-기준)를 충족할 때 완료한다. 브라우저 시연과 같이 쓸 잔량과 원인 기록을 자동 검수에서도 대조한다.
